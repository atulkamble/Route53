What is AWS Route 53?

Amazon Route 53 is a highly available and scalable Domain Name System service provided by AWS.

Route 53 converts domain names into destinations such as IP addresses or AWS resources.
User | | www.example.com v DNS Resolver | v Route 53 | +------> EC2 | +------> ALB | +------> CloudFront | +------> S3 | +------> API Gateway

Route 53 Core Features

Domain Registration

Purchase and manage domains directly through AWS.

DNS Management

Create and manage A, AAAA, CNAME, MX, TXT and other DNS records.

Traffic Routing

Control how DNS traffic is distributed between application endpoints.

Health Checks

Monitor endpoints and route traffic away from unhealthy resources.

Disaster Recovery

Configure primary and secondary resources using failover routing.

Global DNS

Route 53 is a global AWS service used to route users to regional or global applications.

Hosted Zones

Public Hosted Zone

Used for public internet DNS.


Example:

www.atulkamble.in

Private Hosted Zone

Used for private DNS resolution within associated Amazon VPCs.


Example:

database.internal

Important DNS Records

Record Purpose Example
A Maps hostname to IPv4 www.example.com → 54.10.20.30
AAAA Maps hostname to IPv6 www.example.com → IPv6 address
CNAME Maps hostname to another hostname blog.example.com → www.example.com
Alias Route 53 record for supported AWS resources example.com → ALB
MX Mail routing Google Workspace / Microsoft 365
TXT Verification and email security SPF / DKIM / domain verification
NS Authoritative DNS servers Route 53 name servers

Route 53 Alias Record

Alias records are a Route 53 feature designed to route traffic to supported AWS resources.

Application Load Balancer
Network Load Balancer
CloudFront
API Gateway
S3 Website Endpoint
For an ALB, use a Route 53 Alias record instead of storing an ALB IP address.

Route 53 Routing Policies

Simple

Basic DNS routing to one or more resources.

Weighted

Distribute DNS traffic using percentages.


Example

80% → Version 1

20% → Version 2

Latency

Route users to the AWS endpoint that provides the lowest latency.

Failover

Route traffic between primary and secondary resources.

Geolocation

Route traffic based on the geographic location of DNS queries.

Geoproximity

Route traffic based on geographic proximity with optional traffic biasing.

Multivalue Answer

Return multiple healthy DNS records.

Weighted Routing Example

Route 53 | Weighted Routing / \ / \ 80% 20% | | v v Version 1 Version 2

Common use cases include canary releases, gradual migration, A/B testing and blue-green deployment.

Route 53 → EC2 Architecture

User Browser | | www.atulkamble.in v Route 53 | A Record | v EC2 Public IPv4 | v Web Server
When an A record points directly to EC2, use a stable IPv4 address such as an Elastic IP if the DNS destination must remain unchanged.

Route 53 → ALB Architecture

Internet User | v www.atulkamble.in | v Route 53 | A Alias | v Application Load Balancer | v Target Group / \ / \ v v EC2-1 EC2-2

This is a common production architecture because the ALB distributes HTTP/HTTPS requests among healthy application targets.

Health Checks

Route 53 health checks can monitor endpoints using HTTP, HTTPS or TCP.

Route 53 | Health Check | +---------+---------+ | | Healthy Unhealthy | | v v Primary Secondary
Health checks are commonly combined with Failover Routing.

Useful Route 53 Commands

List Hosted Zones

aws route53 list-hosted-zones

List DNS Records

aws route53 list-resource-record-sets \
--hosted-zone-id ZONE_ID

List Health Checks

aws route53 list-health-checks

DNS Lookup

nslookup www.atulkamble.in

DNS Query

dig www.atulkamble.in

Check Name Servers

dig NS atulkamble.in

Points to Remember

  • Route 53 is a global DNS service.
  • DNS commonly uses UDP/TCP port 53.
  • A record maps a hostname to IPv4.
  • AAAA maps a hostname to IPv6.
  • CNAME maps one hostname to another hostname.
  • Alias records can point to supported AWS resources.
  • Use an Alias record for an Application Load Balancer.
  • Weighted routing distributes DNS responses using configured weights.
  • Latency routing routes based on AWS-measured latency.
  • Failover routing is commonly used for disaster recovery.
  • Geolocation routing uses the geographic origin of DNS queries.
  • Health checks detect unhealthy endpoints.
  • TTL controls how long DNS responses can be cached.
  • Route 53 does not replace Security Groups, NACLs or load balancers.
